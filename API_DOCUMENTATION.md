# EaseIntro API - Документация

## Описание

EaseIntro API - это RESTful API для управления встречами и участниками. API использует JWT токены для аутентификации и предоставляет функционал для создания встреч, регистрации участников, управления QR-кодами и многое другое.

## Базовый URL

```
http://localhost:5000/api
```

Для production:
```
https://your-domain.com/api
```

## Аутентификация

API использует JWT (JSON Web Tokens) для аутентификации. После успешного входа (`POST /api/auth/login`), вы получите токен, который необходимо передавать в заголовке `Authorization` для защищенных endpoints:

```
Authorization: Bearer {your_token}
```

Токен действителен в течение 3 часов.

## Rate Limiting

Для защиты от брутфорс-атак, endpoints аутентификации (`/api/auth/*`) имеют ограничение: **5 запросов в минуту** с одного IP-адреса.

При превышении лимита возвращается статус `429 Too Many Requests`.

## Коды статусов HTTP

- `200 OK` - Успешный запрос
- `201 Created` - Ресурс успешно создан
- `204 No Content` - Успешный запрос без содержимого
- `400 Bad Request` - Некорректный запрос
- `401 Unauthorized` - Требуется аутентификация
- `403 Forbidden` - Недостаточно прав доступа
- `404 Not Found` - Ресурс не найден
- `429 Too Many Requests` - Превышен лимит запросов
- `500 Internal Server Error` - Внутренняя ошибка сервера

## Endpoints

### Authentication

#### Регистрация пользователя

**POST** `/api/auth/register`

Регистрирует нового пользователя в системе.

**Требования:**
- Пароль должен содержать минимум 6 символов
- Email должен быть уникальным

**Request Body:**
```json
{
  "userEmail": "user@example.com",
  "password": "password123",
  "publicName": "Иван Иванов",
  "publicContact": "ivan@example.com"
}
```

**Response:** `200 OK`
```json
"Пользователь успешно зарегистрирован."
```

**Ошибки:**
- `400 Bad Request` - Email уже зарегистрирован или пароль слишком короткий

---

#### Вход в систему

**POST** `/api/auth/login`

Выполняет аутентификацию пользователя и возвращает JWT токен.

**Request Body:**
```json
{
  "userEmail": "user@example.com",

}
```

**Response:** `200 OK`
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."

```

**Ошибки:**
- `401 Unauthorized` - Неверные учетные данные

#### Создать встречу

**POST** `/api/meets`

**Требуется аутентификация:** Да

Создает новую встречу. Можно сразу добавить участников при создании.

**Request Body:**
```json
{
  "title": "Деловая встреча",
  "date": "2025-12-31T12:00:00Z",
  "location": "Москва, офис",
  "statusId": 1,
  "limitMembers": 10,
  "allowedPlusOne": true,
  "members": [
    {
      "name": "Иван Иванов",
      "companion": "С супругой",
      "contact": "ivan@example.com",
      "role": 0
    }
  ]
}
```

**Поля:**
- `title` (required, max 160) - Название встречи
- `date` (required) - Дата и время встречи (не может быть в прошлом)
- `location` (required, max 260) - Место проведения
- `statusId` (required, 1-5) - ID статуса встречи (см. Статусы встреч)
- `limitMembers` (optional, default 0) - Лимит участников (0 = без лимита)
- `allowedPlusOne` (optional, default false) - Разрешено ли приводить +1
- `members` (optional) - Массив участников для добавления при создании

**Статусы встреч:**
- `1` - Встреча запланирована
- `2` - Встреча в процессе
- `3` - Встреча завершена
- `4` - Встреча отменена
- `5` - Открыто для регистрации

**Роли участников:**
- `0` - Main (Основной)
- `1` - Admin (Администратор)
- `2` - Staff (Персонал)
- `3` - Guest (Гость, по умолчанию)

**Response:** `201 Created`
```json
{
  "uid": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "title": "Деловая встреча",
  "date": "2025-12-31T12:00:00Z",
  "location": "Москва, офис",
  "status": {
    "title": "Встреча запланирована",
    "description": "Встреча запланирована"
  },
  "limitMembers": 10,
  "allowedPlusOne": true,
  "members": [...],
  "owner": {...}
}
```

**Ошибки:**
- `400 Bad Request` - Дата в прошлом, превышен лимит участников, или некорректные данные

**Request Body:**

```json
"Это ваш уникальный идентификатор: abc123..."
```

**Ошибки:**
- `400 Bad Request` - Контакт уже зарегистрирован на эту встречу
- `404 Not Found` - Встреча не найдена

**Примечание:** Комбинация `contact` + `meetUid` должна быть уникальной.

#### Сканировать QR-код участника для отметки посещения

**GET** `/api/members/qrcode/{qrcode}`

**Требуется аутентификация:** Нет (публичный endpoint)

Публичный endpoint для сканирования QR-кодов обычной камерой телефона. При сканировании автоматически проверяется время мероприятия и отмечается участник, если время подходящее.

**Логика работы:**
- Если указано время мероприятия (например, 7 января в 19:00): можно сканировать за 3 часа до начала (с 16:00)
- Если указана только дата (время = 00:00:00): можно сканировать в день мероприятия
- Если время неподходящее (например, сейчас 6 января, а мероприятие 7 января) - QR остается действительным, участник не отмечается
- Если время подходящее и участник еще не отмечен - автоматически отмечается время прихода, QR становится недействительным
- Если участник уже отмечен - QR недействителен

**Параметры:**
- `qrcode` (string) - QR-код участника

**Response:** `200 OK` (время подходящее, участник отмечен)
```json
{
  "member": {
    "name": "Иван Иванов",
    "companion": "С супругой",
    "contact": "ivan@example.com",
    "role": "Main"
  },
  "meetInfo": {
    "title": "Деловая встреча",
    "date": "2025-12-31T19:00:00Z",
    "location": "Москва, офис"
  },
  "qrValid": false,
  "message": "Участник успешно отмечен",
  "checkedInAt": "2025-12-31T16:30:00Z",
  "isCheckedIn": true
}
```

**Response:** `200 OK` (время неподходящее, QR действителен)
```json
{
  "member": {
    "name": "Иван Иванов",
    "companion": "С супругой",
    "contact": "ivan@example.com",
    "role": "Main"
  },
  "meetInfo": {
    "title": "Деловая встреча",
    "date": "2025-12-31T19:00:00Z",
    "location": "Москва, офис"
  },
  "qrValid": true,
  "message": "Сканирование возможно не ранее 31.12.2025 16:00 (за 3 часа до начала мероприятия)",
  "checkedInAt": null,
  "isCheckedIn": false
}
```

**Response:** `200 OK` (участник уже отмечен, QR недействителен)
```json
{
  "member": {
    "name": "Иван Иванов",
    "companion": "С супругой",
    "contact": "ivan@example.com",
    "role": "Main"
  },
  "meetInfo": {
    "title": "Деловая встреча",
    "date": "2025-12-31T19:00:00Z",
    "location": "Москва, офис"
  },
  "qrValid": false,
  "message": "QR-код уже использован. Участник был отмечен ранее.",
  "checkedInAt": "2025-12-31T16:30:00Z",
  "isCheckedIn": true
}
```

**Ошибки:**
- `404 Not Found` - QR-код не найден

```bash
Authorization: Bearer {token}
```

6. **Сканирование QR-кода на входе (публичный endpoint, можно просто камерой):**
```bash
GET /api/members/qrcode/{qrCode}
# Автоматически проверяет время и отмечает участника, если время подходящее
```

7. **Получение статистики посещаемости:**
```bash
GET /api/meets/{meetUid}/attendance
Authorization: Bearer {token}
```

8. **Выгрузка статистики в CSV:**
```bash
GET /api/meets/{meetUid}/attendance/export
Authorization: Bearer {token}
```

## Безопасность

1. **JWT токены** - Используются для аутентификации защищенных endpoints
2. **Rate limiting** - Защита auth endpoints от брутфорс-атак
3. **Проверка владельца** - Только владелец может изменять/удалять свои встречи и участников
4. **Валидация данных** - Все входные данные валидируются
5. **Хеширование паролей** - Пароли хранятся в захешированном виде (BCrypt)
6. **HTTPS** - В production рекомендуется использовать HTTPS
